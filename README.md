# 兽药出入库记录可追溯系统 · 多端同步版 (v2.0)

在「本地版」(见 `../kc`) 基础上增加**后端同步**：手机 / 电脑访问同一个服务地址，即共用同一份账本，任意一端录入，其他端自动同步。

- 前端：`public/` 下 `index.html` + `app.js` + `styles.css`（与本地版同一套 UI 与业务逻辑，仅数据层改为「本地缓存 + 后端实时同步」）
- 后端：`server.js`（**纯 Node、零依赖**，数据落 `data/db.json` 文件）
- 同步算法：按记录级 `_u`（更新时间戳）合并，天然支持多端并发编辑；设置项（经办人 / 领用单位等）自动并集

> 本地版 (`../kc`) 保持独立可用，互不干扰。

---

## 一、本地运行（电脑上自己用）

需要 Node.js ≥ 16。

```bash
cd kc-sync
node server.js
# 默认 http://localhost:3000
```

浏览器打开 `http://localhost:3000` 即可。同一台电脑上再开一个标签页 / 另一台同局域网设备输 `http://<电脑内网IP>:3000`，两边录入会互相同步。

自定义端口 / 令牌：

```bash
PORT=8080 API_TOKEN=mysecret node server.js
# 带令牌访问：http://localhost:8080/?token=mysecret
```

## 二、让手机也能访问（三种方式）

### 方式 A：本机 + 内网穿透（最快，适合先试用）
在自己电脑运行 `node server.js`，再用隧道工具把 3000 端口暴露到公网，手机扫链接即用：

```bash
# cloudflared（推荐，无需账号）
cloudflared tunnel --url http://localhost:3000

# 或 ngrok
ngrok http 3000
```

隧道工具会给出一个 `https://xxxx.trycloudflare.com` 之类地址，手机浏览器打开即可。
（本机/电脑关机则链接失效，适合临时或长期开着一台机器。）

### 方式 B：部署到免费的 Node 平台（长期稳定）
把 `kc-sync` 整个目录上传到 Render / Railway / Fly.io / 任意支持 Node 的平台，启动命令填 `node server.js`，分配端口用环境变量 `PORT`。
- 建议设置环境变量 `API_TOKEN` 做基本保护。
- 部署后把平台给的网址发给保管员，手机直接打开。

### 方式 C：自有服务器 / 内网
放到公司内网一台常开机器的 3000 端口，手机连同一网络访问；或挂到 nginx 反向代理 + 域名。

## 三、数据与备份

- 账本数据保存在后端服务器的 `data/db.json`，所有访问该服务的设备共享它。
- 前端仍会在**本机浏览器**缓存一份，断网时也能查看、录入（恢复网络后自动同步）。
- 定期在「数据备份」页导出 **JSON / CSV** 备份；JSON 可在「导入」整库恢复。
- 「清空数据」会**同时清空服务器**，操作前请先备份。

---

## 四、同步行为说明

| 操作 | 同步效果 |
|------|----------|
| 任一端新增 / 编辑 / 删除 | 约 0.8 秒后自动推送到服务器，其他端 30 秒轮询拉取；也可点右上角「↻ 同步」立即同步 |
| 两端改了**同一条**记录 | 以 `_u` 时间戳较新的一方为准（后保存的覆盖先保存的） |
| 两端各新增不同记录 | 两边都有（按 id 合并，互不丢失） |
| 经办人 / 领用单位等设置 | 自动取并集，新增的会出现在所有端 |
| 载入示例 / 导入备份 / 清空 | 整体覆盖服务器（replace 模式） |

右上角状态：**已同步 / 同步中… / 离线(本地) / 同步失败 / 令牌错误**。

## 五、接口一览（供二次开发）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET  | `/api/state` | 获取合并后的全量账本 |
| POST | `/api/sync`   | 增量合并推送（按 `_u` 取新） |
| POST | `/api/replace`| 整体覆盖（载入示例 / 导入 / 清空） |
| POST | `/api/reset`  | 清空服务器数据 |

若设置了 `API_TOKEN`，所有 `/api` 请求需在 URL 带 `?token=` 或请求头 `x-token`。
